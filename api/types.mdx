`react-native-nitrowind` ships with first-class TypeScript types generated by the [Nitrogen](https://github.com/mrousavy/nitro) codegen tool. The types live in `src/specs/nitrowind.nitro.ts` and are kept in sync with the native Swift and Kotlin implementations automatically. You get full IDE autocompletion and compile-time safety without any manual type declarations.

---

## `Nitrowind` interface

The `Nitrowind` interface is the TypeScript spec that drives both the JS API and the native code generation. It extends `HybridObject` and declares every method that the native module exposes.

```ts
import type { HybridObject } from "react-native-nitro-modules";

export interface Nitrowind extends HybridObject<{ ios: "swift"; android: "kotlin" }> {
  sum(num1: number, num2: number): number;
}
```

<Expandable title="Interface breakdown">

**`HybridObject<{ ios: 'swift'; android: 'kotlin' }>`**

The generic argument tells Nitrogen which native language to target on each platform. Setting `ios: 'swift'` means the generated spec class (`HybridNitrowindSpec`) is a Swift protocol; setting `android: 'kotlin'` means it becomes an abstract Kotlin class. Your native implementations — `HybridNitrowind.swift` and `HybridNitrowind.kt` — must conform to or extend these generated specs respectively.

**`sum(num1: number, num2: number): number`**

Declares a synchronous method that accepts two `number` arguments and returns a `number`. On the native side, `number` maps to `Double` in both Swift and Kotlin:

```swift
// iOS — HybridNitrowind.swift
func sum(num1: Double, num2: Double) throws -> Double {
    return num1 + num2
}
```

```kotlin
// Android — HybridNitrowind.kt
override fun sum(num1: Double, num2: Double): Double {
    return num1 + num2
}
```

</Expandable>

## `HybridObject` (from `react-native-nitro-modules`)

`HybridObject` is the foundational base type provided by `react-native-nitro-modules`. It represents any native object that can be bridged to JavaScript through the Nitro runtime. The generic parameter constrains which native languages are required for each platform.

You do **not** implement `HybridObject` yourself. The `Nitrowind` singleton is already created for you by `NitroModules.createHybridObject()` at module load time — you only ever interact with the pre-built instance:

```ts
import { NitroModules } from "react-native-nitro-modules";
import type { Nitrowind as NitrowindSpec } from "./specs/nitrowind.nitro";

export const Nitrowind = NitroModules.createHybridObject<NitrowindSpec>("Nitrowind");
```

## Usage with TypeScript

Because `Nitrowind` is fully typed via its interface, you can annotate variables explicitly or rely on inference — either way, the compiler tracks the exact return type of every method call.

```ts
import { Nitrowind } from 'react-native-nitrowind';

// Nitrowind is fully typed — hover to see method signatures
const result: number = Nitrowind.sum(5, 10); // result: 15
```

Passing a wrong type raises a compile-time error before the code ever reaches a device:

```ts
// ❌ TypeScript error: Argument of type 'string' is not assignable to parameter of type 'number'
const bad = Nitrowind.sum("5", 10);
```
