## v0.1.0

**Initial release** — published to npm under the MIT license.

### New features

<Accordion title="Nitrowind.sum(num1, num2) — synchronous native addition">
The first native method shipped with `react-native-nitrowind`. `sum` performs integer addition entirely on the native thread via the JSI bridge — no async bridge hop, no JSON serialisation overhead.

```typescript
import { Nitrowind } from 'react-native-nitrowind';

const result = Nitrowind.sum(3, 7);
console.log(result); // 10
```

The method is implemented in:

- **iOS** — Swift, using the Nitro Modules Swift bridge
- **Android** — Kotlin, using the Nitro Modules Kotlin bridge

Both platforms share the same C++ spec so the behaviour is identical across environments.
</Accordion>

<Accordion title="Full TypeScript type safety via Nitro Modules spec">
All public APIs are described in a Nitro spec file and code-generated by `nitrogen`. This means:

- Every method signature is statically typed end-to-end — from the TypeScript call site down to the native implementation.
- Type errors surface at compile time, not at runtime.
- No manual type casting is needed when calling native methods.

The generated TypeScript types are shipped in the `lib/typescript` directory and are automatically resolved when you install the package.
</Accordion>

<Accordion title="Bare React Native 0.76+ and Expo SDK 57 support">
`react-native-nitrowind` v0.1.0 targets the two most common project setups:

| Environment | Minimum version |
|---|---|
| Bare React Native | 0.76 |
| Expo SDK | 57 (React Native 0.86) |
| Node.js | 18 |

The package ships an `app.plugin.js` Expo Config Plugin so that Expo managed-workflow projects can include the native module in a development build without writing custom native code.

<Note>
Nitro Views require React Native 0.78 or later. If you are on 0.76 or 0.77 you still get full access to synchronous JSI methods; only the view layer requires the newer minimum.
</Note>
</Accordion>

<Accordion title="Codegen support via nitrogen">
The full code-generation pipeline is available out of the box. Run the `codegen` script from the package root to regenerate all C++, Swift, and Kotlin bridge files from the Nitro spec:

```bash
bun run codegen
```

Under the hood this calls `nitrogen --logLevel="debug"`, runs the TypeScript build with `bob`, and executes the post-processing script. You only need this if you fork the library and change the spec — consuming applications never need to run codegen themselves.
</Accordion>

<Accordion title="React Native autolinking support">
`react-native-nitrowind` fully supports React Native's autolinking mechanism. After installing the package you do not need to run `react-native link` or add any manual linking configuration.

For iOS, run `pod install` once after install and CocoaPods will pick up the podspec automatically:

```bash
cd ios && pod install
```

For Android, Gradle resolves the module through the standard `react-native.config.js` entry that ships with the package.
</Accordion>
