The Android implementation of `react-native-nitrowind` is written in Kotlin. The `HybridNitrowind` class extends the Nitro-generated `HybridNitrowindSpec` and is registered through `NitrowindPackage`, which initialises the native C++ library via the NDK at startup. React Native's autolinking discovers and registers the package automatically — no changes to `MainApplication` are required.

## Requirements

- **React Native 0.76+** — required for the Nitro Modules architecture
- **Android Studio** (Electric Eel or later recommended)
- **Android NDK** — required for the C++ JSI bridge layer that connects Kotlin to the JavaScript engine
- **`minSdkVersion` 24+** — the standard React Native minimum SDK requirement

## Setup

<Steps>
  <Step title="Add the package">
    Install `react-native-nitrowind` from your project root:

    ```bash
    npm install react-native-nitrowind
    # or
    yarn add react-native-nitrowind
    # or
    bun add react-native-nitrowind
    ```
  </Step>

  <Step title="Autolinking (no manual steps needed)">
    React Native's autolinking detects `NitrowindPackage` automatically when you build. You do not need to edit `MainApplication.kt`, `settings.gradle`, or any Gradle file manually.

    If you are on an older React Native version that does not support autolinking, add the package manually in `MainApplication.kt`:

    ```kotlin
    import com.nitrowind.NitrowindPackage

    override fun getPackages(): List<ReactPackage> =
        PackageList(this).packages.apply {
            add(NitrowindPackage())
        }
    ```
  </Step>

  <Step title="Build and run">
    Launch your app on an emulator or connected device:

    ```bash
    npx react-native run-android
    # or
    bun run android
    ```

    Gradle compiles the Kotlin sources and the CMake/NDK C++ bridge in a single build step.
  </Step>
</Steps>

## Kotlin implementation

The native logic lives in `android/src/main/java/com/nitrowind/HybridNitrowind.kt`. The class extends the Nitro-generated `HybridNitrowindSpec`, which defines the JavaScript-visible API surface:

```kotlin
package com.nitrowind

import com.margelo.nitro.nitrowind.HybridNitrowindSpec

class HybridNitrowind: HybridNitrowindSpec() {
    override fun sum(num1: Double, num2: Double): Double {
        return num1 + num2
    }
}
```

`HybridNitrowindSpec` is generated by the Nitro codegen tool from your TypeScript spec. `HybridNitrowind` provides the concrete Kotlin implementation — here a `sum` function that adds two `Double` values and returns the result directly to JavaScript with zero serialisation overhead.

## Package registration

`NitrowindPackage` extends `BaseReactPackage` and handles module registration. Its companion object calls `NitrowindOnLoad.initializeNative()` in a static initialiser, loading the compiled C++ shared library (`Nitrowind`) the moment the package is first referenced:

```kotlin
package com.nitrowind;

import com.facebook.react.bridge.NativeModule
import com.facebook.react.bridge.ReactApplicationContext
import com.facebook.react.module.model.ReactModuleInfoProvider
import com.facebook.react.BaseReactPackage
import com.margelo.nitro.nitrowind.NitrowindOnLoad

public class NitrowindPackage : BaseReactPackage() {
  override fun getModule(name: String, reactContext: ReactApplicationContext): NativeModule? = null

  override fun getReactModuleInfoProvider(): ReactModuleInfoProvider = ReactModuleInfoProvider { emptyMap() }

  companion object {
    init {
      NitrowindOnLoad.initializeNative();
    }
  }
}
```

Key points:

- `BaseReactPackage` is the new-architecture base class; it replaces the older `ReactPackage` interface used in bridge-mode React Native.
- Returning `null` from `getModule` and an empty map from `getReactModuleInfoProvider` is correct — Nitro modules expose themselves through the JSI, not through the legacy bridge module registry.
- `NitrowindOnLoad.initializeNative()` is generated by Nitro and calls `System.loadLibrary("Nitrowind")` to load the C++ shared object defined by `androidCxxLibName` in `nitro.json`.

<Note>
  The NDK and CMake are required because `react-native-nitrowind` uses a C++ JSI bridge layer between Kotlin and the JavaScript engine. Nitro generates C++ glue code (a `cpp-adapter.cpp`) that is compiled by CMake into the `Nitrowind` shared library at build time. Without the NDK installed, the Gradle build will fail with a CMake configuration error.
</Note>

<Tip>
  Make sure the NDK is installed before building. Open **Android Studio → SDK Manager → SDK Tools**, check **NDK (Side by side)**, and click **Apply**. Use the NDK version that matches your React Native release — check `android/build.gradle` in your project for the `ndkVersion` property.
</Tip>
