The iOS implementation of `react-native-nitrowind` is written entirely in Swift. The `HybridNitrowind` class extends the generated `HybridNitrowindSpec` protocol and is distributed as a CocoaPods pod via the `Nitrowind.podspec`. React Native's autolinking, combined with Nitro's own autolinking configuration in `nitro.json`, wires everything together automatically — no manual native registration is required.

## Requirements

- **React Native 0.76+** — required for the Nitro Modules architecture
- **React Native 0.78+** — required if you use Nitro Views
- **Xcode 15+**
- **CocoaPods** (install with `sudo gem install cocoapods` if needed)

## Setup

<Steps>
  <Step title="Add the package">
    Install `react-native-nitrowind` from your project root:

    ```bash
    npm install react-native-nitrowind
    # or
    yarn add react-native-nitrowind
    # or
    bun add react-native-nitrowind
    ```
  </Step>

  <Step title="Run pod install">
    Navigate to your project's `ios/` directory and run CocoaPods to fetch the native pod:

    ```bash
    cd ios && pod install
    ```

    CocoaPods reads `Nitrowind.podspec`, pulls in the Swift sources, and runs the Nitrogen-generated autolinking Ruby script (`Nitrowind+autolinking.rb`) automatically.
  </Step>

  <Step title="Open the Xcode workspace">
    Always open the `.xcworkspace` file, not the `.xcodeproj`, so that CocoaPods dependencies are included:

    ```bash
    open ios/YourApp.xcworkspace
    ```
  </Step>

  <Step title="Build and run">
    Build and launch your app on a simulator or device directly from Xcode, or use the React Native CLI:

    ```bash
    npx react-native run-ios
    ```
  </Step>
</Steps>

## Swift implementation

The native logic lives in `ios/HybridNitrowind.swift`. The class conforms to the Nitro-generated `HybridNitrowindSpec` protocol, which defines the JavaScript-visible API surface:

```swift
//
//  HybridNitrowind.swift
//  Pods
//
//  Created by Aristote Ngoy on 9/9/2026.
//

import Foundation

class HybridNitrowind: HybridNitrowindSpec {
    func sum(num1: Double, num2: Double) throws -> Double {
        return num1 + num2
    }
}
```

`HybridNitrowindSpec` is generated by the Nitro codegen tool from your TypeScript spec. `HybridNitrowind` provides the concrete implementation — in this case a `sum` function that adds two `Double` values and returns the result.

## CocoaPods distribution

The `Nitrowind.podspec` describes the pod to CocoaPods and wires in all required source files:

```ruby
require "json"

package = JSON.parse(File.read(File.join(__dir__, "package.json")))

Pod::Spec.new do |s|
  s.name         = "Nitrowind"
  s.version      = package["version"]
  s.summary      = package["description"]
  s.homepage     = package["homepage"]
  s.license      = package["license"]
  s.authors      = package["author"]

  s.platforms    = { :ios => min_ios_version_supported, :visionos => 1.0 }
  s.source       = { :git => "https://github.com/aristotengoy/react-native-nitrowind.git", :tag => "#{s.version}" }

  s.source_files = [
    # Implementation (Swift)
    "ios/**/*.{swift}",
    # Autolinking/Registration (Objective-C++)
    "ios/**/*.{m,mm}",
    # Implementation (C++ objects)
    "cpp/**/*.{hpp,cpp}",
  ]

  load 'nitrogen/generated/ios/Nitrowind+autolinking.rb'
  add_nitrogen_files(s)

  s.dependency 'React-jsi'
  s.dependency 'React-callinvoker'
  install_modules_dependencies(s)
end
```

Key points:

- The podspec picks the minimum supported iOS version automatically via `min_ios_version_supported`, so you do not need to hard-code a deployment target.
- It also declares `visionos => 1.0` support out of the box.
- `add_nitrogen_files(s)` injects the Nitro-generated C++ glue that bridges Swift into the JSI layer.
- `install_modules_dependencies(s)` pulls in React Native's new architecture dependencies.

<Note>
  The Swift class `HybridNitrowind` is resolved and registered automatically through the `autolinking` section of `nitro.json`:

  ```json
  "autolinking": {
    "Nitrowind": {
      "ios": {
        "language": "swift",
        "implementationClassName": "HybridNitrowind"
      }
    }
  }
  ```

  Nitro reads this configuration at build time and generates the Objective-C++ glue that maps `HybridNitrowind` into the JSI bridge — you never write registration code by hand.
</Note>

<Tip>
  Run `pod install` again every time you update `react-native-nitrowind` to a new version. The podspec version is tied to the npm package version, so CocoaPods needs to re-fetch and regenerate the autolinking Ruby file after an upgrade.
</Tip>
